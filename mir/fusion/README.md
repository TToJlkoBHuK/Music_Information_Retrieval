# mir/fusion — слияние видео- и аудиоканалов

**Ядро научной новизны работы.** Ни один из существующих проектов не использует оба канала одновременно: видео-парсеры игнорируют звук, аудио-транскрипторы не видят картинку. Здесь два независимых списка нот сверяются друг с другом.

## Идея

У каждого канала свои сильные и слабые места, и они почти не пересекаются:

| Ошибка | Видео | Аудио |
|---|---|---|
| Блик, артефакт сжатия | ложная нота | не влияет |
| Нота вне кадра (обрезанная клавиатура) | пропуск | распознаёт |
| Быстрая трель | сливается в одну ноту | разделяет |
| Плотный аккорд | видны все клавиши | нижние ноты маскируются |
| Тихая нота | видна подсветка | может потеряться |
| Реверберация, шум записи | не влияет | размывает границы |

Нота, найденная обоими каналами, почти наверняка настоящая. Нота из одного канала требует решения — и решение принимается не наугад, а по тому, какая это ошибка и какому каналу в этой ситуации доверять.

## Файлы

## `matcher.py`

```python
@dataclass
class MatchConfig:
    onset_tolerance: float = 0.08  # допуск по времени, секунды
    pitch_tolerance: int = 0  # 0 = высота должна совпадать точно
    duration_weight: float = 0.3  # вес длительности в функции стоимости


@dataclass
class MatchResult:
    pairs: list[tuple[NoteEvent, NoteEvent]]  # (видео, аудио)
    video_only: list[NoteEvent]
    audio_only: list[NoteEvent]


def match_notes(
    video_notes: list[NoteEvent], audio_notes: list[NoteEvent], config: MatchConfig
) -> MatchResult:
    """
    Сопоставление как задача о назначениях.

    Наивный жадный проход (для каждой ноты видео ищем ближайшую
    по времени ноту аудио той же высоты) ломается на аккордах
    и повторяющихся нотах: одна нота аудио может «притянуть»
    несколько нот видео.

    Правильное решение: венгерский алгоритм
    (scipy.optimize.linear_sum_assignment) на матрице стоимостей.

        cost[i][j] = |onset_i - onset_j|
                   + duration_weight * |dur_i - dur_j|
                   + INF, если pitch_i != pitch_j
                   + INF, если |onset_i - onset_j| > onset_tolerance

    Сложность O(n³) в худшем случае, но задача разбивается
    по высотам (ноты разной высоты не сопоставляются никогда),
    поэтому фактически это 88 маленьких задач вместо одной большой.
    """
```

Разбиение по высотам — не оптимизация ради оптимизации: без него на десятиминутном ролике с тысячами нот венгерский алгоритм считается неприлично долго.

## `resolver.py`

Самая содержательная часть модуля: что делать с нотами, найденными только одним каналом.

```python
@dataclass
class ResolverContext:
    layout: KeyboardLayout  # знаем, обрезана ли клавиатура
    video_quality: float  # оценка качества видеоканала
    audio_quality: float
    tempo: TempoMap


def resolve_video_only(note: NoteEvent, ctx: ResolverContext) -> NoteEvent | None:
    """
    Нота есть в видео, но не в аудио. Возможные причины:

    1. Ложное срабатывание: блик, артефакт сжатия, эффект визуализатора
       → отбросить
    2. Нота настоящая, но замаскирована в аудио (тихая, внутри плотного
       аккорда, забита реверберацией)
       → оставить с пониженной confidence

    Признаки в пользу настоящей ноты:
      - в этот момент звучит аккорд (есть подтверждённые ноты рядом
        по времени) — маскировка вероятна
      - высокая confidence от CV-модуля
      - длительность типична для произведения, а не 1–2 кадра

    Признаки в пользу ложной:
      - изолирована во времени (вокруг тишина, но аудио её не слышит)
      - очень короткая
      - низкая confidence детекции
    """


def resolve_audio_only(note: NoteEvent, ctx: ResolverContext) -> NoteEvent | None:
    """
    Нота есть в аудио, но не в видео. Возможные причины:

    1. Нота за пределами кадра — если layout.is_cropped и высота ноты
       вне [lowest_pitch, highest_pitch], это почти наверняка так
       → оставить с высокой confidence, hand=UNKNOWN
    2. Блок перекрыт водяным знаком или эффектом
       → оставить со средней confidence
    3. Галлюцинация модели (обертон принят за ноту)
       → отбросить

    Главный признак галлюцинации: нота ровно на октаву или дуодециму
    выше подтверждённой ноты, начинается одновременно с ней
    и короче её. Это классическая ошибка спектральных методов.
    """
```

**Определение руки для нот из аудио.** Аудиоканал не знает про руки. Если нота пришла только из аудио, `hand=UNKNOWN`, и решение откладывается до этапа `notation`, где руки определяются по высоте и голосоведению.

## `merger.py`

```python
def merge(
    video_result: VisionResult, audio_result: AudioResult, tempo: TempoMap, config: FusionConfig
) -> FusionResult:
    """
    Полная последовательность:
      1. estimate_av_offset → apply_offset (выравнивание)
      2. match_notes (сопоставление)
      3. для пар — объединение атрибутов
      4. для одиночек — resolve_video_only / resolve_audio_only
      5. сортировка по onset, дедупликация

    Правило объединения атрибутов пары:
      pitch      ← из видео (позиция клавиши однозначна)
      onset      ← из аудио (разрешение в 3–6 раз выше)
      offset     ← из видео (длина блока точнее, чем затухание звука)
      velocity   ← из аудио (модель обучена на реальной динамике,
                             яркость подсветки — лишь косвенная оценка)
      hand       ← из видео (по цвету блока)
      source     ← Source.BOTH
      confidence ← 1 - (1-c_v)(1-c_a), формула объединения независимых оценок
    """


@dataclass
class FusionResult:
    notes: list[NoteEvent]
    av_offset: float
    stats: FusionStats


@dataclass
class FusionStats:
    matched: int
    video_only_kept: int
    video_only_dropped: int
    audio_only_kept: int
    audio_only_dropped: int

    @property
    def agreement_rate(self) -> float:
        """Доля согласия каналов. Хорошая метрика качества разбора:
        если ниже 0.6 — что-то пошло не так, стоит предупредить."""
```

Таблица правил объединения атрибутов — прямой ответ на вопрос «в чём новизна вашей работы». Каждая строка обоснована: берётся тот канал, который в этом конкретном атрибуте объективно точнее.

## Что тестировать

Здесь тесты особенно важны — модуль легко сломать незаметно.

- **Синтетика.** Из известного MIDI генерируется и видео, и аудио. Тогда ground truth точный, и можно проверить, что слияние даёт F1 выше, чем каждый канал по отдельности. Это же — главный график экспериментальной главы.
- Искусственный сдвиг аудио на N мс — `estimate_av_offset` должен его найти.
- Аккорд из 4 нот: венгерский алгоритм не должен схлопнуть их в одну.
- Обрезанная клавиатура: ноты вне диапазона обязаны сохраниться.
- Обертон на октаву выше — должен отсеяться.
