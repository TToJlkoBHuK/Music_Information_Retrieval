# mir/ingest — загрузка и подготовка материала

Первый этап конвейера. Превращает то, что дал пользователь (ссылку или файл), в два готовых к анализу потока: видеоряд и аудиодорожку.

## Файлы

```
ingest/
├── downloader.py    скачивание по ссылке (yt-dlp)
├── demuxer.py       разделение на видео и аудио (FFmpeg)
├── cache.py         кэш скачанных роликов
└── sources.py       распознавание платформы по URL
```

## `downloader.py`

```python
@dataclass
class DownloadOptions:
    proxy: str | None = None  # "socks5://127.0.0.1:1080"
    max_height: int = 1080  # выше 1080 смысла нет, только время
    prefer_fps: int = 60  # если доступно — берём, точнее трекинг
    timeout: int = 300


class Downloader:
    def __init__(self, cache: MediaCache, options: DownloadOptions): ...

    def fetch(self, source: str, progress: Callable[[float], None] | None = None) -> Path:
        """
        Вход:  URL или путь к локальному файлу
        Выход: путь к видеофайлу на диске
        Бросает: DownloadError с человекочитаемым user_message
        """

    def probe(self, url: str) -> VideoInfo:
        """Метаданные без скачивания: название, длительность,
        доступные разрешения. Нужно, чтобы показать пользователю,
        что именно будет качаться, и оценить время."""
```

**Выбор качества.** Чем выше разрешение и fps, тем точнее распознавание: при 60 fps шаг между кадрами 16 мс вместо 33, что вдвое улучшает временное разрешение трекинга блоков. Но 4K тянуть смысла нет — клавиатура и блоки уверенно различимы уже на 1080p, а время скачивания и декодирования растёт квадратично. Отсюда потолок 1080p с приоритетом высокого fps.

**Обработка ошибок.** Все исключения yt-dlp переводятся в `DownloadError` с русским сообщением:

| Ситуация | Сообщение пользователю |
|---|---|
| Нет соединения с YouTube | «Не удалось подключиться к YouTube. Проверьте VPN или укажите прокси в настройках» |
| Видео удалено / приватное | «Видео недоступно: оно удалено или закрыто автором» |
| Возрастное ограничение | «Видео с возрастным ограничением скачать не удалось» |
| Не тот тип ссылки | «Это ссылка на плейлист. Укажите ссылку на конкретное видео» |

## `demuxer.py`

```python
class Demuxer:
    def split(self, video_path: Path, work_dir: Path) -> MediaBundle:
        """
        Вход:  скачанный или локальный видеофайл
        Выход: MediaBundle с путями к видео и извлечённому аудио

        Аудио извлекается в WAV 16 кГц моно — именно такой формат
        ждёт модель транскрипции ByteDance. Пересэмплирование
        делает FFmpeg, это быстрее и качественнее librosa.
        """

    def probe(self, video_path: Path) -> tuple[float, float, int, int]:
        """(fps, duration, width, height) через ffprobe.

        fps берётся как r_frame_rate дробью (например 30000/1001),
        а не округлённым: при часовом ролике ошибка округления
        29.97 → 30 накапливается в несколько секунд рассинхрона."""
```

Команда извлечения аудио:

```
ffmpeg -i input.mp4 -vn -acodec pcm_s16le -ar 16000 -ac 1 audio.wav
```

Видео при этом не перекодируется — `vision` читает исходный файл через OpenCV покадрово. Перекодирование заняло бы минуты и потеряло бы качество, важное для детекции.

## `cache.py`

```python
class MediaCache:
    def __init__(self, root: Path = Path.home() / ".mir_cache"): ...

    def key_for(self, url: str) -> str:
        """Ключ = sha256 от нормализованного URL."""

    def get(self, url: str) -> Path | None: ...
    def put(self, url: str, path: Path) -> Path: ...
    def clear(self, older_than_days: int | None = None) -> int:
        """Вернуть количество освобождённых байт."""
```

Кэш нужен по практической причине: при подборе параметров пользователь запускает разбор одного ролика много раз. Качать заново каждый раз — минуты ожидания и лишняя нагрузка на VPN.

## Контракт этапа

```python
def ingest(source: str | Path, options: DownloadOptions,
           progress: ProgressCallback | None = None) -> MediaBundle
```

Вход — строка от пользователя. Выход — `MediaBundle` (описан в `common/README.md`): пути к видео и аудио, fps, длительность, разрешение, название.

## Что тестировать

- `normalize_url` на разных формах ссылок YouTube (`youtu.be`, `&t=`, `&list=`)
- `detect_platform` на всех поддерживаемых платформах и на мусоре
- `probe` возвращает дробный fps без округления
- работа кэша: повторный `fetch` не лезет в сеть
- перевод ошибок yt-dlp в `DownloadError` с непустым `user_message`
