# mir/eval — метрики качества

Сравнение результата распознавания с эталоном по правилам MIREX для задачи Note Tracking — тем же, по которым меряются работы в этой области.

Своя формула сделала бы числа несопоставимыми с публикациями, а сравнение с аналогами — главный аргумент в пользу проекта.

## Правила сопоставления

* нота засчитана, если **высота совпала точно**, а начало отличается не более чем на 50 мс;
* соответствие **взаимно однозначное**: одна найденная нота закрывает ровно одну эталонную, дубли идут в ложные срабатывания;
* **длительность проверяется отдельной метрикой** (`f1_with_offset`): она хуже определяется и по звуку, и по видео, поэтому в публикациях приводится отдельно.

Октавная ошибка — промах, а не «почти верно»: `evaluate([до первой], [до второй])` даёт F1 = 0.

## Использование

```python
from mir.eval import evaluate

score = evaluate(truth, result)
print(score.format_report())
print(score.f1, score.precision, score.recall)
```

## Почему F-мера, а не доля найденных

Гармоническое среднее точности и полноты, а не обычное: система, нашедшая все ноты вместе с тысячей лишних, не должна получать половину балла.

## Сопоставление жадное

Для каждой эталонной ноты берётся ближайшая свободная найденная той же высоты, в порядке времени. Полное решение задачи о назначениях дало бы на доли процента больше совпадений ценой кубической сложности — на роликах в тысячи нот это неоправданно.

## Точность руки считается только по определённым

`hand_accuracy` берётся от числа нот, у которых рука определена в обоих списках. Ролик с одноцветной схемой не получает нулевую оценку за то, что честно вернул «рука неизвестна»; вместо этого `hand_known` показывает, по скольким нотам вообще было что сравнивать.
