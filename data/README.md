# data — тестовые материалы

Папка под материал для отладки и оценки качества. **В git не коммитится** (кроме этого файла) — видео весит много, а на ролики распространяются авторские права.

## Структура

```
data/
├── videos/         исходные ролики для тестов
├── ground_truth/   эталонные ноты к ним
└── output/         результаты прогонов (перезаписывается)
```

## `videos/` — что сюда положить

Набор нужно подобрать так, чтобы он покрывал реальное разнообразие роликов. Ориентир — по 3–5 штук на каждую категорию:

| Категория | Зачем |
|---|---|
| Классический Synthesia, 1080p 60fps | базовый случай, на нём всё должно работать идеально |
| Низкое качество (480p, низкий битрейт) | проверка устойчивости CV к артефактам сжатия |
| Обрезанная клавиатура | видны не все 88 клавиш — проверка `assignPitches` |
| Нестандартная цветовая схема | тёмная тема, необычные цвета блоков |
| С эффектами | свечение, частицы при нажатии, водяные знаки |
| Одноцветные блоки | руки не различаются по цвету — проверка эвристик в `staves` |
| Живое исполнение с rubato | плавающий темп, проверка квантизации |
| Быстрые пассажи, трели | проверка временного разрешения |
| Реальная клавиатура (съёмка сверху) | не симуляция, а видеозапись инструмента |
| Разные размеры: 3/4, 6/8 | проверка `meter` вне 4/4 |

Файлы именовать осмысленно: `synthesia_1080p60_chopin_nocturne.mp4`, `cropped_keyboard_low_bitrate.mp4`. Рядом держать `videos/index.csv` с описанием:

```csv
filename,platform,resolution,fps,category,notes
synthesia_1080p60_chopin.mp4,youtube,1920x1080,60,baseline,"эталонный случай"
cropped_5oct_480p.mp4,youtube,854x480,30,cropped,"видно 5 октав из 7"
```

## `ground_truth/` — эталоны

Для каждого ролика, по которому считаются метрики, нужен эталон в виде MIDI или CSV с колонками `pitch,onset,offset,velocity,hand`.

Три способа его получить, по убыванию трудоёмкости:

1. **Официальные ноты автора.** Если у ролика есть купленные или бесплатные ноты — импортировать их в MuseScore, выровнять по времени, экспортировать MIDI. Самый достоверный вариант.
2. **Ручная разметка.** Разбор в DAW покадрово. Часы работы на минуту музыки — оправдано только для 1–2 коротких фрагментов.
3. **Синтетика.** Сгенерировать видео из известного MIDI (см. `tests/README.md`). Эталон бесплатный и точный, но картинка искусственная — не заменяет реальные ролики, а дополняет их.

Разумная стратегия: основная масса метрик считается на синтетике (много данных, точный эталон), а 3–5 реальных роликов размечаются вручную для проверки, что на настоящем материале цифры не разваливаются. Расхождение между синтетикой и реальностью — само по себе интересный результат для экспериментальной главы.

## `output/` — результаты

Сюда пайплайн складывает MIDI, MusicXML и PDF при прогонах. Содержимое временное, чистится свободно.

Для сохранения результатов экспериментов заводить подпапки с датой: `output/2026-08-15_fusion_ablation/`.

## Про авторские права

Ролики скачиваются для исследовательских целей и не распространяются. В репозиторий попадают только ссылки (`videos/index.csv`), а не сами файлы. Если в дипломе приводится фрагмент нотного листа, полученного из чужого ролика, стоит указать источник и что это результат автоматической транскрипции.

Вопрос почти наверняка прозвучит на защите — лучше иметь готовый ответ.
