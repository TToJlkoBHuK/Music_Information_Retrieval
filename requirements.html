    Требования к системе¶

    Задача #14. Техническое задание, зафиксированное до начала разработки.

    Идентификаторы (F-01, NF-01) нужны, чтобы на этапе тестирования ссылаться на конкретное требование и показать в записке покрытие.

    Границы задачи¶

    Что система делает. Принимает piano-visualizer-ролик (Synthesia-подобный формат: клавиатура внизу, падающие блоки сверху), распознаёт сыгранные ноты и выдаёт читаемый нотный лист для фортепиано.

    Чего система не делает — важно оговорить сразу, иначе на защите это прозвучит как недоработка:

    • не распознаёт ноты с обычной видеозаписи концерта без визуализации;
    • не работает с инструментами кроме фортепиано;
    • не разбирает ролики со снятой под углом клавиатурой (нужна была бы гомография);
    • не выделяет партию фортепиано из ансамбля;
    • не претендует на редакторскую точность издания — результат требует вычитки музыкантом.

    Функциональные требования¶

    Ввод¶

    ID Требование Приоритет
    F-01 Загрузка ролика по ссылке YouTube Обязательно
    F-02 Открытие локального видеофайла (mp4, mkv, webm) Обязательно
    F-03 Работа при включённом VPN без настройки со стороны пользователя Обязательно
    F-04 Поддержка VK Видео и Rutube Желательно
    F-05 Кэширование скачанных роликов Желательно

    F-03 — не опция, а необходимость: из России YouTube без VPN недоступен, без этого требования продукт неработоспособен у целевой аудитории.

    Как это выполняется. Музыкант привык нажать одну кнопку в VPN-клиенте и забыть. Требовать от него ещё и настройку прокси недопустимо, поэтому:

    1. Готовое приложение — обычный процесс Windows, и режим TUN (перехват всего системного трафика) покрывает его автоматически. Настраивать нечего.
    2. Если прямое соединение не прошло — например, VPN-клиент работает в режиме Proxy, а не TUN, — программа сама перебирает типичные порты локальных клиентов и повторяет попытку.
    3. Ручной ввод адреса остаётся в настройках, но нужен лишь в редких случаях: нестандартный порт или внешний прокси.

    Ручная настройка требовалась только в контейнере Docker при разработке: у WSL2 собственный сетевой стек, туннель Windows на него не распространяется. К конечному продукту это отношения не имеет.

    Распознавание¶

    ID Требование Приоритет
    F-06 Автоматическая детекция клавиатуры без участия пользователя Обязательно
    F-07 Корректная работа при обрезанной клавиатуре (видны не все 88 клавиш) Обязательно
    F-08 Распознавание нот по видеоряду (подсветка клавиш и падающие блоки) Обязательно
    F-09 Распознавание нот по аудиодорожке Обязательно
    F-10 Слияние двух каналов с взаимной проверкой Обязательно
    F-11 Компенсация рассинхрона аудио и видео Обязательно
    F-12 Автокалибровка под разные цветовые схемы визуализаторов Желательно
    F-13 Распознавание педали Желательно

    F-06 — ключевое отличие от video2midi, где калибровка ручная. F-10 — заявленная новизна работы.

    Нотный текст¶

    ID Требование Приоритет
    F-14 Определение темпа Обязательно
    F-15 Определение тональности Обязательно
    F-16 Определение тактового размера и расстановка тактовых черт Обязательно
    F-17 Квантизация длительностей с настраиваемой жёсткостью Обязательно
    F-18 Расстановка пауз Обязательно
    F-19 Разделение на два стана (скрипичный и басовый ключ) Обязательно
    F-20 Динамические оттенки из velocity Желательно
    F-21 Обработка затакта Желательно

    Блок F-14…F-19 — то, чего не делает ни один открытый аналог.

    Выход¶

    ID Требование Приоритет
    F-22 Экспорт в MIDI Обязательно
    F-23 Экспорт в MusicXML Обязательно
    F-24 Экспорт в PDF Обязательно
    F-25 Заголовок с названием произведения и ссылкой на источник Желательно
    F-26 Пометка «автоматическая транскрипция» в выходных файлах Желательно

    F-23 принципиален: он признаёт, что автоматика ошибается, и даёт пользователю возможность доправить результат в MuseScore. Закрытые сервисы часто отдают только PDF.

    Интерфейс¶

    ID Требование Приоритет
    F-27 Полностью русский интерфейс Обязательно
    F-28 Русская музыкальная терминология (до/ре/ми, «ре мажор», «четвертная») Обязательно
    F-29 Сценарий в три шага: вставил ссылку → нажал кнопку → получил PDF Обязательно
    F-30 Прогресс по этапам обработки Обязательно
    F-31 Ручное переопределение темпа, тональности, размера Обязательно
    F-32 Пересборка нот без повторного разбора видео Обязательно
    F-33 Предпросмотр нот в окне программы Желательно
    F-34 Отображение достоверности результата (совпадение каналов) Желательно
    F-35 Понятные сообщения об ошибках вместо стектрейсов Обязательно

    F-32 — требование к архитектуре, а не только к интерфейсу: полный разбор идёт минуты, подбор параметров должен быть мгновенным. Отсюда разделение Pipeline.run() и Pipeline.rebuild().

    Нефункциональные требования¶

    Производительность¶

    ID Требование Значение
    NF-01 Время обработки ролика на GPU ≤ 1× длительности ролика
    NF-02 Время обработки на CPU ≤ 4× длительности ролика
    NF-03 Время пересборки нот (rebuild) ≤ 5 секунд
    NF-04 Потребление памяти ≤ 4 ГБ

    Ориентир NF-01: ролик на 4 минуты обрабатывается не дольше 4 минут. Значения предварительные, уточняются по результатам этапа 8 — важно зафиксировать их сейчас, чтобы было с чем сравнивать.

    Точность¶

    ID Требование Значение
    NF-05 Note F1 на роликах хорошего качества (1080p, 30+ fps) ≥ 0.90
    NF-06 Note F1 на роликах низкого качества (480p) ≥ 0.75
    NF-07 Точность определения тональности ≥ 0.80
    NF-08 Ошибка определения темпа ≤ 2 %
    NF-09 Доля нот в правильной руке ≥ 0.90
    NF-10 Слияние каналов не хуже лучшего одиночного канала обязательно

    Метрики считаются через mir_eval.transcription с допуском onset 50 мс — стандарт MIREX (см. literature-review.md). Это позволяет сопоставлять результаты с опубликованными.

    NF-10 — критическое требование: если слияние не даёт выигрыша, заявленная новизна не подтверждается. Проверяется скриптом scripts/ablation.py.

    Совместимость и развёртывание¶

    ID Требование
    NF-11 Работа на Windows 10/11 (основная платформа)
    NF-12 Работа без GPU
    NF-13 Установщик не требует установленного Python и компилятора
    NF-14 Размер дистрибутива ≤ 500 МБ (веса модели скачиваются отдельно)
    NF-15 Работоспособность на Linux (сборка из исходников)

    Качество кода¶

    ID Требование
    NF-16 Типизация Python, проверка mypy --strict
    NF-17 Покрытие тестами ключевых алгоритмов (notation, fusion) ≥ 70 %
    NF-18 Все настраиваемые пороги вынесены в конфиг, без магических чисел в коде
    NF-19 Логирование через logging, интерфейс перехватывает лог

    NF-18 — не педантизм: в записке придётся обосновывать каждый порог, и удобно, когда они собраны в одном месте (config/README.md).

    Ограничения проекта¶

    Ограничение Следствие
    Языки C++ и Python Зафиксировано условиями работы; C++ — CV-ядро и GUI, Python — логика
    Срок — до защиты Приоритеты «обязательно» выполняются, «желательно» — по остатку времени
    Один разработчик Модель транскрипции берётся готовая, движок вёрстки — тоже
    Отсутствие размеченных данных Основные метрики считаются на синтетике из известных MIDI
    Авторские права на ролики Результаты не распространяются, в репозиторий попадают только ссылки

    Сценарии использования¶

    Основной. Музыкант нашёл ролик, хочет ноты. Вставляет ссылку, ждёт несколько минут, получает PDF, печатает.

    С правкой. Ноты получены, но тональность определена неверно. Пользователь выбирает правильную в настройках, нажимает пересборку, через секунды видит исправленный результат (F-31, F-32).

    Без интернета. Ролик скачан заранее другим способом. Пользователь открывает локальный файл (F-02).

    Для доработки. Музыкант хочет отредактировать результат в MuseScore. Экспортирует MusicXML (F-23).

    Приёмка¶

    Работа считается выполненной, когда:

    1. Все требования приоритета «обязательно» реализованы;
    2. NF-05…NF-09 подтверждены измерениями на тестовом наборе;
    3. NF-10 подтверждено экспериментом ablation.py — слияние выигрывает у одиночных каналов;
    4. Собран установщик под Windows, проверенный на чистой системе;
    5. Есть демонстрация: ролик → нотный лист, записанная на видео (на защите может не быть интернета).
