    mir/notation — превращение событий в нотный текст¶

    Второй по важности модуль после fusion. Именно здесь решается задача, на которой останавливаются все открытые аналоги: они выдают сырой MIDI, а читаемых нот не дают.

    В чём разница между MIDI и нотами¶

    MIDI — это «нота 60 звучала с 1.234 по 1.712 секунды». Нотный текст — это «четвертная нота до первой октавы на первой доле третьего такта в тональности ре мажор, партия правой руки».

    Чтобы пройти этот путь, нужно восстановить информацию, которой в MIDI просто нет:

    Чего нет в MIDI Как восстанавливаем
    Тональность профильный алгоритм Крумхансля–Шмуклера
    Тактовый размер периодичность акцентов
    Границы тактов сетка долей + первая сильная доля
    Паузы заполнение промежутков между нотами
    Нотные длительности квантизация к музыкальной сетке
    Распределение по станам цвет блоков или голосоведение
    Диез или бемоль следует из тональности

    Файлы¶

    notation/
├── quantizer.py       события → музыкальная сетка
├── key_detector.py    определение тональности
├── meter.py           тактовый размер и границы тактов
├── rests.py           расстановка пауз
├── staves.py          распределение по двум станам
├── dynamics.py        velocity → динамические оттенки
└── builder.py         сборка Transcription

    Порядок вызова важен: квантизация → размер → тональность → станы → паузы → динамика. Паузы ставятся последними, потому что для них нужны уже известные такты и станы.

    quantizer.py¶

    @dataclass
class QuantizeConfig:
    strength: float = 0.7  # 0 = не трогать, 1 = жёстко в сетку
    max_subdivision: int = 16  # мельчайшая допустимая длительность
    allow_triplets: bool = True
    min_duration_beats: float = 0.0625  # короче — считаем мусором


def quantize(
    notes: list[NoteEvent], tempo: TempoMap, config: QuantizeConfig
) -> list[QuantizedNote]:
    """
    Вход:  события в секундах + временна́я сетка
    Выход: события с позициями и длительностями в долях

    Формула компромисса:
        new_pos = old_pos + strength * (grid_pos - old_pos)

    При strength=1 нота встаёт точно в узел сетки, при 0 остаётся
    как есть. Это не косметика: жёсткая квантизация убивает
    rubato и делает запись механической, мягкая — порождает
    нечитаемый лес из лиг, точек и синкоп.

    Выбор узла сетки: для каждой ноты перебираются кандидаты
    (1/4, 1/8, 1/16, триоли если разрешены), выбирается тот,
    что даёт минимальную суммарную ошибку по началу и длительности.
    """


@dataclass(frozen=True)
class QuantizedNote:
    event: NoteEvent
    start_beat: float  # позиция в долях от начала
    duration_beats: Fraction  # именно Fraction, не float
    is_triplet: bool = False

    Почему Fraction, а не float. Длительности должны складываться точно: три триоли обязаны дать ровно одну долю, а 0.333 * 3 = 0.999 ломает проверку заполненности такта. Fraction(1,3) * 3 == 1 — точно. Это мелочь, которая экономит часы отладки.

    key_detector.py¶

    # Профили Крумхансля–Кесслера: усреднённая по экспериментам
# «уместность» каждой из 12 ступеней в мажоре и миноре
MAJOR_PROFILE = [6.35, 2.23, 3.48, 2.33, 4.38, 4.09, 2.52, 5.19, 2.39, 3.66, 2.29, 2.88]
MINOR_PROFILE = [6.33, 2.68, 3.52, 5.38, 2.60, 3.53, 2.54, 4.75, 3.98, 2.69, 3.34, 3.17]


def detect_key(notes: list[NoteEvent], weight_by_duration: bool = True) -> KeyDetectionResult:
    """
    Вход:  события
    Выход: тональность + уверенность + альтернативы

    Алгоритм:
      1. Гистограмма по 12 ступеням (pitch % 12).
         Вес ноты = её длительность: половинная нота
         значит для тональности больше, чем проходящая шестнадцатая.
      2. Для каждой из 24 тональностей — коэффициент корреляции
         Пирсона между гистограммой и повёрнутым профилем.
      3. Максимум = ответ, разрыв с вторым местом = уверенность.
    """


@dataclass
class KeyDetectionResult:
    key: str  # "D major", "B minor"
    confidence: float
    alternatives: list[tuple[str, float]]  # топ-3 для показа в интерфейсе
    sharps_flats: int  # +2 = два диеза, -3 = три бемоля

    Почему это критично. Без тональности каждая чёрная клавиша записывается случайным диезом, и нотный лист покрывается десятками случайных знаков. В ре мажоре фа-диез и до-диез выставляются один раз при ключе — и текст становится читаемым. Ровно на этом спотыкается импорт сырого MIDI в MuseScore.

    Известная слабость. Параллельные тональности (до мажор и ля минор) имеют одинаковые ключевые знаки и очень похожие гистограммы. Алгоритм различает их по тому, какая нота чаще стоит в сильной позиции и завершает фразы. Ошибка здесь не портит ключевые знаки, только подпись тональности.

    staves.py¶

    def assign_staves(measures: list[Measure], use_hand_hints: bool = True) -> list[Measure]:
    """
    Если у нот есть hand из видеоканала — берём его, это надёжнее всего.

    Иначе эвристика:
      1. Базовое правило: до первой октавы (pitch 60) — граница.
         Выше — скрипичный ключ, ниже — басовый.
      2. Поправка на голосоведение: минимизируем сумму скачков
         внутри каждой партии. Изолированная нота, попавшая
         «не в свою» руку, создаёт неестественный скачок.
      3. Перекрещивание рук: если левая рука уходит выше правой
         (бывает в фактуре), правило по высоте даёт мусор.
         Ловится по разрыву в голосоведении.

    Ноты с hand=UNKNOWN (пришли только из аудио) прогоняются
    через эвристику даже при use_hand_hints=True.
    """

    rests.py¶

    def fill_rests(measure: Measure, beats_per_bar: int) -> Measure:
    """
    Найти промежутки без нот на каждом стане и закрыть паузами.

    Правила нотной записи, которые нельзя нарушать:
      - сумма длительностей в такте = размер такта, точно;
      - пауза не пересекает границу доли — длинная пауза
        разбивается на несколько (например, в 4/4 пауза
        на 3 доли пишется как половинная + четвертная,
        а не как половинная с точкой);
      - целотактовая пауза пишется одним знаком независимо
        от размера;
      - если на стане в такте вообще нет нот — целотактовая пауза.

    Здесь и пригождается Fraction: проверка «сумма == размер»
    должна быть точной, иначе MuseScore при импорте
    ругается на переполненный такт.
    """

    velocity → динамические оттенки.

    Что тестировать¶

    • квантизация: последовательность с известным ритмом должна дать ожидаемые длительности при strength=1
    • триоли не должны схлопываться в восьмые
    • detect_key на фрагментах в заведомо известных тональностях (взять из готовых MIDI)
    • find_anacrusis на произведении с затактом
    • сумма длительностей в каждом такте равна размеру — это инвариант, проверять на всех тестовых данных
    • перекрещивание рук: искусственный пример, где левая выше правой
